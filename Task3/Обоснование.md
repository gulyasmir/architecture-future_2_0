# Обоснование этапов Roadmap


| Этап                                                                                         | Зачем нужен                                                                                                                                                                                                                                      | Польза для бизнеса                                                                                                                                                                                 |
| ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **1–3 месяц**<br/> Проектирование                                            | Спроектировать целевую архитектуру, выделить домены, выбрать технологический стек, запустить первые отчёты через новую витрину данных. | Минимизировать архитектурные риски, заложить масштабируемую основу, быстро показать первую ценность для бизнеса. |
| **4–6 месяц**<br/> Построение базы данных и шины событий   | Развернуть новый DWH, внедрить Kafka/RabbitMQ для событийного обмена, разделить данные по доменам.                                                                                      | Ускорить построение аналитики, обеспечить независимость бизнес-направлений, повысить безопасность данных.             |
| **7–9 месяц**<br/> Миграция микросервисов и логики             | Вынести бизнес-логику из старого DWH, подключить новых партнёров, запустить Data Mart Portal для пилотных пользователей.                                              | Ускорить вывод новых продуктов, разгрузить IT-команды за счёт self-service аналитики, увеличить бизнес-гибкость.                 |
| **10–12 месяц**<br/> Финализация и поддержка, вывод легаси | Завершить миграцию данных, отключить устаревшие системы (SQL Server 2008, Power Builder, Apache Camel), ввести Data Lake.                                                                           | Существенно сократить затраты на поддержку, повысить надёжность и масштабируемость платформы для будущего роста. |

## Карту рисков проекта

Что будет, если не перейти вовремя на новую архитектуру.


| Риск                                                                         | Причина возникновения                                                                                                | Последствия для бизнеса                                                                                                         | Вероятность | Влияние         | План действий                                                                                                 |
| -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| **Деградация производительности старого DWH** | SQL Server 2008 устарел, объёмы данных растут                                                                   | Долгое построение отчётов, потеря скорости принятия решений, потеря клиентов       | Высокая         | Критическое | Срочная миграция на новый DWH и разнесение доменов                                |
| **Невозможность интеграции новых бизнесов**  | Старый монолит не поддерживает масштабирование                                                 | Заморозка роста, невозможность выхода на новые рынки (фармацевтика, электроника) | Высокая         | Критическое | Внедрение шины событий и микросервисной архитектуры                         |
| **Рост стоимости поддержки легаси**                  | Устаревшие технологии требуют дорогих специалистов и затрат на поддержку | Постоянное увеличение IT-бюджета, снижение маржи бизнеса                                              | Средняя         | Высокое         | Планомерный вывод легаси-систем, переквалификация команд                |
| **Риски безопасности данных**                             | Медицинские и финансовые данные не изолированы                                                  | Штрафы за нарушение законодательства (GDPR, HIPAA), потеря репутации                                 | Средняя         | Критическое | Разделение данных по доменам и внедрение новых политик доступа      |
| **Потеря конкурентного преимущества**             | Медленная аналитика, отсутствие self-service решений для бизнеса                            | Более быстрые конкуренты займут рынок, падение доли рынка                                           | Средняя         | Высокое         | Быстрая разработка Data Mart Portal и self-service BI                                                   |
| **Устаревание ИТ-компетенций команды**            | Работа с легаси-технологиями тормозит развитие специалистов                         | Отток квалифицированных кадров, ухудшение производительности                                  | Средняя         | Среднее         | Переобучение на современные технологии (NestJS, Kafka, Kubernetes)                     |
| **Риски при миграции данных**                              | Ошибки в процессе переноса данных                                                                           | Потеря данных, прерывание бизнес-процессов                                                                      | Низкая           | Критическое | Организация поэтапной миграции и многоступенчатого тестирования |

Самые **критические риски**: деградация производительности, невозможность масштабирования бизнеса, риски безопасности данных.

Без модернизации архитектуры:

* Бизнесу будет трудно расти.
* Увеличатся прямые расходы на IT.
* Появится риск крупных штрафов и потери репутации.

При реализации Roadmap:

* Бизнес будет гибким, быстрым и конкурентоспособным.
* IT-подразделение станет ускорителем роста, а не тормозом.
