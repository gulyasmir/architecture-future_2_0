# **Приоритетные проблемы**


### Приоритизация проблем по MoSCoW:


| Проблемная область                                        | Приоритет (MoSCoW) | Обоснование                                                                                                                                                                                             |
| -------------------------------------------------------------------------- | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| DWH на старом SQL Server 2008                                      | **Must have**               | Без миграции на современную платформу дальнейшее развитие невозможно.                                                                                 |
| Большая бизнес-логика в DWH                            | **Must have**               | Нужно вынести бизнес-логику в сервисы, чтобы масштабировать и интегрировать новые компании.                                          |
| Медленная генерация отчётов в BI                 | **Must have**               | Скорость принятия решений критична для бизнеса, сейчас слишком долго.                                                                                   |
| Данные медицинские и финансовые смешаны | **Must have**               | Нужно срочно разделить для соблюдения законодательства (например, GDPR, HIPAA).                                                                           |
| Трудности интеграции новых бизнесов        | **Should have**             | Важно для роста, но можно временно обойтись «костылями», если критически нужно что-то быстро интегрировать.              |
| Старая интеграционная шина (Apache Camel)          | **Should have**             | Желательно заменить на современный брокер событий (например, Kafka), но это не блокирует существующую работу.                |
| Отсутствие чётких доменных границ            | **Should have**             | Стратегически важно, но можно чуть позже выделить полноценные домены.                                                                                   |
| Power Builder интерфейс                                           | **Could have**              | Сильно мешает, но напрямую не блокирует проекты по данным. Можно обновить позже, уже после создания витрины данных. |


Must have (срочно нужно делать):

* Миграция DWH
* Вынос бизнес-логики
* Разделение данных (медицина ≠ финансы)
* Ускорение отчётности BI

Should have (желательно в первой волне):

* Подготовка интеграций под новые бизнесы
* Замена шины
* Выделение доменов

Could have (позже):

* Миграция интерфейсов операторов
